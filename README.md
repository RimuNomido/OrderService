# OrderService

Учебный backend-сервис для работы с пользователями, товарами и заказами.

Проект делаю в процессе изучения Python Backend. Основная цель — разобраться на практике с FastAPI, SQLAlchemy, PostgreSQL, транзакциями и тестированием.

## Возможности

В проекте реализованы:

- создание и получение товаров;
- создание заказов;
- получение заказа;
- получение заказов пользователя;
- проверка существования пользователя и товара;
- проверка количества товара на складе;
- уменьшение остатка товара после создания заказа;
- обработка ошибок бизнес-логики;
- работа с миграциями базы данных;
- асинхронные тесты.

## Конкурентные заказы

Отдельно я разбирался с ситуацией, когда два пользователя одновременно пытаются заказать последний товар.

Для этого при создании заказа используется блокировка строки в PostgreSQL:

```sql
SELECT ... FOR UPDATE
```

Перед изменением остатка товар блокируется внутри транзакции. Благодаря этому два конкурентных запроса не могут одновременно изменить один и тот же остаток.

Для этой ситуации также написан тест, который одновременно запускает два заказа на товар с остатком `1`. В результате один заказ создаётся, а второй получает ошибку недостаточного количества товара.

Также есть тест конкурентного добавления одинакового товара.

## Основные модели

### User

Пользователь сервиса.

### Product

Товар. Содержит информацию о цене и количестве товара на складе.

### Order

Заказ пользователя.

### OrderItem

Позиция заказа. Связывает заказ с товаром и хранит количество и цену товара на момент создания заказа.

## Работа с базой данных

Для работы с PostgreSQL используется асинхронный SQLAlchemy и `AsyncSession`.

В проекте я использовал:

- ORM-модели;
- связи между таблицами;
- транзакции;
- `flush`;
- `commit` и `rollback`;
- блокировки `SELECT ... FOR UPDATE`;
- обработку `IntegrityError`.

Изменения структуры базы данных выполняются через Alembic.

## Тестирование

Для тестирования используются `pytest` и `pytest-asyncio`.

Проверяются в том числе:

- создание заказа;
- ошибки при отсутствии пользователя или товара;
- недостаточный остаток товара;
- конкурентное создание заказов;
- конкурентное добавление товара.

## Запуск

Для работы проекта необходим PostgreSQL.

После настройки подключения к базе данных нужно применить миграции:

```bash
alembic upgrade head
```

Затем можно запустить FastAPI-приложение.

Тесты запускаются командой:

```bash
pytest
```
